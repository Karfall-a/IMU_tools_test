Тестирование IMU_tools пакета
=================

Обзор
--------

В данном репозитории содержится тестируемый пакет для фильтрации и визуализации данных IMU-датчиков imu_tools и пакет для запуска и тестирования фильтров на данных `imu_dataset.db3`. 

Установка
----------

### Предварительные требования

- Ubuntu 20.04
- ROS2 Galactic

### Установка из репозитория

1. Создайте рабочее пространство:
	`mkdir -p ~/ros2_ws/src`
	`cd ~/ros2_ws/src`
2. Клонируйте в созданную папку репозиторий:
	`git clone https://github.com/Karfall-a/IMU_tools_test.git`
3. Соберите пакет:
	`colcon build`
4. Не забудьте обновить среду:
	`source ~ros2_ws/install/setup.bash`

Поздравляем, Вы успешно справились с установкой!

Основные возможности
---------

Данный репозиторий представляет возможность тестирования и применения пакета imu_tools на данных, полученных в задании (далее - демо), и на любых других rosbag-файлах, содержащих IMU данные. А точнее:
- Запуск различных IMU фильтров (madgwick, complementary)
- Воспроизведение данных из rosbag-файлов
- Автоматическая настройка Rviz2 для визуализации
- Гибкая конфигурация через параметры запуска launch-файла

Ход работы
----------------------------

### Анализ работы imu_tools

Пакет imu_tools содержит в себе фильтры imu_complementary_filter и imu_filter_madgwick, а также встраиваемый плагин для Rviz2 для визуализации данных из IMU-датчиков. В рамках изучения пакета были найдены и устранены следующие ошибки:
- Неверные параметры для запуска узлов в launch-файлов (node_executable вместо executable, node_name вместо name)
- Устаревшие сведения об использовании плагина rviz_imu_plugin (Указана необходимость выбора /imu вместо /imu_link как Fixed Frame)

### Разработка пакета

Для быстрой настройки параметров и запуска визуализации был разработан пакет `imu_launcher`, который содержит:
- Launch-файл для одновременного запуска rosbag-файла, фильтра и Rviz2, в рамках которого созданы отдельные параметры для быстрого переключения между фильтрами и тестовыми данными
- Конфигурации Rviz для исключения необходимости ручной настройки Rviz под выбранный фильтр
- Rosbag-директория для хранения тестовых данных, в том числе демо-данные

### Выбор фильтра

При выборе фильтра приоритет был отдан фильтру Complementary как менее строгому математически по сравнению с фильтром Madgwick. При недостаточной точности работы Complementary фильтра будет произведена замена на фильтр Madgwick.

### Настройка параметров 

Согласно [оригинальной статье](https://www.mdpi.com/1424-8220/15/8/19302), коррекция работы фильтра основана на мультипликативной технике. По результатам обработки данных акселерометра происходит коррекция тангажа и крена, после чего при наличии данных магнетометра происходит коррекция рысканья.
В пакете imu_tools доступны следующие параметры, которые применимы для коррекции фильтра:
- use_mag (использует данные с магнитометра)
- constant_dt (постоянный временной шаг)
- gain_acc (увеличение делает большую чувствительность к данным акселерометра и увеличивает чувствительность к скачкам данных акселерометра)
- gain_mag (аналогично как с gain_acc, но для магнитометра, неактивно при use_mag=0)
- do_bias_estimation (принимает корректировку по смещению значений угловых скоростей)
- bias_alpha (определение частоты среза для фильтра низких частот для корректировки значений смещения)
- do_adaptive_gain (делает коэфф усиления акселерометра функцией, зависящей от изменения текущего вектора гравитации, с максимальным значением в gain_acc и минимальным в 0)
- orientation_stddev (стандартное отклонение выходной ориентации от реальной) (нужно при использовании нескольких датчиков)

Также при необходимости вручную в коде можно изменить определение состояния покоя для работы корректировки смещения (kAccelerationTreshold, kAngularVelocityTreshold, kDeltaAngularVelocityTreshold в complementary_filter.cpp). Таким же образом можно изменить параметры ошибок для максимального и минимального значений adaptive gain (error1, error2), однако это не рекомендуется, так как выставленные настройки [являются оптимальными согласно автору статьи](https://www.mdpi.com/1424-8220/15/8/19302). 

#### Порядок настройки фильтра

1. Параметр **constant_dt** настроен на 0. При проверке частоты обновления данных с датчика установить значение constant_dt, равное 1/частота.
2. Датчик находится в статическом состоянии. Настраиваем **gain_acc** с отключенными данными магнитометра и без корректировки смещения угловых скоростей до максимально большого значения, при котором шумы остаются незначительными.
3.  Датчик находится в статическом состоянии. Включаем данные с магнитометра и настраиваем **gain_mag** до максимально большого значения, при котором шумы и дрейф остаются незначительными до максимально большого значения, при котором шумы и дрейф остаются незначительными.
4. Датчик медленно вращается. При перерегулировании уменьшить **gain_acc**.
5. Датчик медленно вращаетсz. При перерегулировании уменьшить gain_mag.
6.  Датчик находится в статическом состоянии минимум 2-3 минуты. При наличии дрейфа включаем do_bias_estimation и настраиваем **bias_alpha**.
7. Датчик вращается с произвольной скоростью во всех осях. Фильтр должен выдавать положение без недорегулирования и перерегулирования. В ином случае вернуться к пункту 2. 
8. При использовании дополнительных датчиков в сочетании с IMU, установить **orientation_stddev** от 0 до 1, где 0 - максимальная степень доверия IMU, а 1 - максимальная степень недоверия.


### Итоги тестирования

После тестирования фильтров при равных настройках (без учёта данных магнитометра и с их учётом с равными коэффициентами gain в обоих случаях) было замечено, что фильтр Madgwick при верных настройках показывает удовлетворительные результаты с данными магнитометра и без них, а при работе фильтра Complementary с данными магнитного поля возникает дрейф. ![Результаты представлены в видео](demo.mp4).
